- 适配器**零改动**：`MaiBot-Napcat-Adapter` 连的仍是 `127.0.0.1:3001`，与 LLBot 的 OneBot 11 正向 WS 默认端口一致；新增 `deploy/qq-pmhq/prepare-config.ps1` 从适配器配置推导 LLBot 配置，端口与 token 两端天然一致。

## DSH 桥（新）

- 新增第一方插件 `plugins/marisa_dsh`（`marisa.dsh`）：把 DeepSeek Harness 接到魔理沙身上，主人可以用 QQ 远程驱动它干活——提交任务、拿回结果、接续会话做迭代。
- 指令：`/dsh 开始`（进入**对话模式**，之后主人直接发普通消息就是在跟 DSH 一轮一轮地说话）、`/dsh 结束`、`/dsh <任务>`（单次任务）、`/dsh 新 <任务>`（另起新会话）、`/dsh 状态` / `会话` / `忘记`；另有 `marisa_dsh_task` / `marisa_dsh_status` 两个工具供模型主动调用（工具默认按只读下发）。
- **过程可视化**（三档，默认不刷屏）：`[stream] mode = off | digest | full`。`digest`（默认）下短任务**一条进度都不发**，长任务每 `digest_interval_sec`（120s）最多一条「⏳ 进行中：N 步 / 用时，最近：工具」，工具**失败**立即推；`full` 才每次工具调用各推一条。只有**主人主动发起**的运行（`/dsh`、对话模式）才推过程，模型自己调 `marisa_dsh_task` 时一律安静、只回最终结果。
- 对话模式走 `chat.receive.before_process` 钩子（`BLOCKING` + `LATE`，让 marisa_gate 的门控先跑）：只接管**处于对话模式且发送者是主人**的普通消息，群友发的话原样放回主链，绝不会被当成 DSH 指令；闲置超时自动退出。
- 子进程 stdout 由独立线程逐行读取后经 `call_soon_threadsafe` 投进 asyncio 队列，不依赖宿主的事件循环策略；stderr 并入 stdout，靠「不以 `{` 开头就跳过」过滤，避免两条管道互相塞死。
- 实现走 DSH 自带的一次性任务入口 `dsh --profile <档> headless --json <任务>`：取 `final.text` 作回答、`session.sessionId` 作可接续会话号、`status.usage` 报 token 用量。任务以参数列表交给子进程（不拼 shell 字符串），`.cmd` 经 `cmd.exe /c` 调用。
- 命令一律 `permission="operator"`，工具再做一次运行时主人校验；每次执行写审计日志 `data/marisa/dsh_audit.log` 并把完整输出落盘 `data/marisa/dsh_runs/`，QQ 只回摘要。
- 会话策略：`/dsh <任务>` **默认接续**本会话上一次的 DSH 会话（不用重述做过什么），`/dsh 新 <任务>` 才干净地另起一次。实测新会话与接续的总 token 几乎相同（固定前缀每轮都要重发，但稳定前缀会命中 prompt cache），所以默认值按"少让主人重述"来选。
- 用量回执把「新增 / 缓存命中 / 输出」分开报，便于判断真实开销。
- 工具 `marisa_dsh_task` 改为**后台提交**：原实现会 inline 等 DSH 跑完（最长 900 秒），模型一旦调用就把整轮对话卡住；现在立刻返回「已提交」，结果由后台任务直接推回会话。工具描述同时补上典型触发场景，自然语言（如「把某个文件夹加进工作区」）现在能被路由过来。

## 细节

- **确认/取消不再靠正则判断意图**：删除 `shell_exec.parse_confirm`（确认/取消词表 + 短句阈值补丁）与 gate 钩子里的两条抢话分支。它曾把主人「…给出一份合理的清理整合建议 不执行文件修改」误判成"取消"，还顺手跑了一次 `shutdown /a`，整条请求被吞掉、根本没到 DSH。现在改为：把待确认清单作为 `〔主人·待确认 P1=…〕` 搭在消息上，**由模型判断这条是不是回执**，再调用新增的 `marisa_pending_list` / `marisa_pending_confirm` / `marisa_pending_cancel` 三个工具；执行侧仍由代码硬校验（编号必须存在、owner 校验、过期即拒），`source=cleanup` 时把**机器拼出的字符串**交给既有清理解析器——正则不再接触用户原话。斜杠指令（`/取消关机`、`/终端` 等）属于语法而非意图，保持确定性路由不变。
- 退役 `/opencode`：AI 远程任务统一交给 DSH（`/dsh`），删掉 `marisa_gate` 的 `marisa_opencode` 工具、`/opencode` 指令、`_run_opencode`/`opencode_action` 与 `execute_pending` 的 opencode 分支，以及 `[terminal]` 的 `timeout_opencode_sec` / `opencode_cmd` 两项配置；`/终端`、`/关闭电脑`、`/取消关机` 与提案-确认、审计机制全部保留。删除后插件内 opencode 引用为 0，`py_compile` 通过，顺带移除因此不再使用的 `shutil` 导入。
- 移除「提醒」功能：删除 `plugins/marisa_desktop/native/reminders.py`，以及 `marisa_desktop` 里与之相关的三个工具（`marisa_reminder_add/list/delete`）、三条指令（`/提醒`、`/提醒列表`、`/提醒删除`）、每分钟对表的后台循环、帮助菜单的「提醒」分类与条目。删除后插件内相关引用为 0，`py_compile` 通过。
- 修复语音发送失败：`plugins/marisa_voice` 的 `[voice] send_mode` 由 `file` 改为 `base64`（代码默认值、字段说明、配置与两处文档同步）。协议端换成容器化的 LLBot 后，`file` 模式发出的本地路径会被适配器补成 `file://D:\…`，LLBot 在容器里找不到该路径并抛「路径不存在」，机器人表现为回一句「语音发送失败了……」。该默认在 NapCat 与宿主同机时成立，换协议端后不再成立。
- `deploy/qq-pmhq/README.md` 新增「媒体路径陷阱」一节：列出 base64 / http / file 三种媒体引用在容器化协议端下的行为差异，并给出图片、视频、`file` 组件等同类问题的排查方法。
- 新增 `deploy/qq-pmhq/`：`Dockerfile.pmhq`、`docker-compose.yml`、`prepare-config.ps1`、`README.md`、`bypass/`（5 个 C 源文件 + PROVENANCE）。
- `start_all.ps1` / `stop_all.ps1`：QQ 侧改为容器生命周期（`docker compose up -d --build` / `down`）。**不要再按 3001/3080 端口杀进程**——那是 Docker 的端口代理，杀掉会打坏 Docker 网络而容器仍在运行。

# [1.0.8] - 学习与Maisaka更新 - 2026-6-25

**注意：此版本改动内容较多，请阅读以下说明**

- Q：为什么更新后麦麦说话太多/太少？
- A：1.0.8更新了maisaka的发言机制，可能对于不同的人设会有不同的变化，你可以 1.修改人设或提示词；2.调整回复频率模式 3.调整回复频率数值 来尝试微调

- Q：为什么表达选择使用了“精细”或者“超级精细”模式后，回复变慢？
- A：这是因为这些模式下，Maisaka需要进行更细致的表达分析，使用LLM和嵌入进行计算，你可以使用更快的嵌入模型，并且修改模型配置中的expression_use模型来加快速度。

- Q：为什么麦麦出现了连续回复或者回复自身？
- A：可以尝试 1.修改planner的提示词 2.开启 聊天-标记自身消息 3.避免使用参数量过小的planner模型 4.修改 聊天 - 什么时候发言 - "连续 wait 上限" ，调低该数值可以降低性能较弱模型的连续回复情况。
